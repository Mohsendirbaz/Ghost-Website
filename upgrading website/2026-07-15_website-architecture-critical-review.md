# Ghost Autonomy Website — Critical Architecture Review

**Subject:** Divergence of the implemented website architecture from the 100-percent-visual web goal
**Date:** July 15, 2026
**Baseline examined:** Working tree of `Ghost Website/` (content layer synced June 10, 2026; exhibition integration session of July 11, 2026, 16:18–21:21 UTC) and the deployed exhibition bundle `public/exhibition/assets/index-xipKf2En.js` (built July 11, 21:21 UTC). Governing goal documents: `upgrading website/2026-07_visual-overhaul-plan-v1.md` and `-v2.md` (both July 9, 2026), read against `2026-07_update-plan-1.md`, `-2.md`, the February briefing set, and the original website-creation prompt.

---

## 1. Executive Summary

The program's own strategy documents define the visual goal with unusual clarity: *"don't decorate the text — replace the text's job."* Each page is to make its argument visually first, with prose demoted to captioning and depth-on-demand; a sitewide visual grammar (evidentiary standings rendered as fill conventions), a blueprint aesthetic, and one flagship interactive exhibition are to carry the site's identity. Measured against that definition, the architecture as implemented remains a text-delivery system that has acquired a visual annex.

Three summary judgments organize this review.

First, **the divergence is structural, not a backlog.** Of the ten interactive visual instruments specified across the two overhaul plans, zero have shipped. What shipped instead — thirteen static SVG plates, twelve PDF cover thumbnails, and an iframed exhibition — is genuine progress, but it was absorbed by the existing architecture as *appended figures inside unchanged prose pages*. This is precisely the "decorate the text" pattern the plan's thesis rejects, and it recurs because the architecture makes text cheap and visuals expensive: prose lives in one importable JavaScript module, while a visual requires a component, styles, tokens, RTL variants, accessibility fallbacks, and a data contract the codebase does not yet supply.

Second, **the single most consequential finding is not aesthetic but governance.** The deployed exhibition bundle — the centerpiece of the visual strategy — publicly contains the Program Coverage Map view and its complete 56-subcategory gap dataset, which overhaul plan v2 classifies as sensitive and mandates be excluded from the public build. The exclusion mechanism exists in the code and is correctly written; the build script never engages it. The website-resident README asserts the coverage files are "physically absent from this copy"; they are present. Site copy advertises "The Four Rooms" while rendering five room cards, the fifth being the sensitive one, in both languages. The mandated pre-deploy bundle assertion exists nowhere. For a program whose declared brand is claim discipline, the deepest divergence from the visual goal is that the pipeline meant to prove visual honesty cannot currently prove where its most sensitive dataset is.

Third, **the visual goal is achievable within the present corpus but not within the present process.** The stack is visual-capable (framer-motion, Mermaid, D3 in the sub-app, an installed but idle sticky-scroll component), the corpus supplies real data for every planned visual, and the July 11 session demonstrated that substantial integration work can land in a day. What the process lacks is subtraction (dead strategies accumulate rather than retire), a build stage where visual assets would naturally be produced and verified, and a single machine-readable register binding sensitivity and standings decisions to what actually deploys.

## 2. The Goal, As the Program Documented It

The phrase "100 percent visual" is operationalized by the program's own consulting documents, and the review adopts their definition rather than an external one.

Plan v1 (July 9) diagnoses the site as "a research program wearing a text costume" and sets the thesis: every page argues visually first; prose is demoted to captions and disclosures; and the spectacles must be *true* — animations that are demonstrations, not metaphors. It specifies a visual grammar system (standings encoded as solid/outline/dashed/hatched/dotted with a reusable sitewide legend component), a blueprint token aesthetic with a cyanotype dark mode, a signature motion verb ("narrowing"), and five signature set-pieces: the animated narrowing hero, the Safety scroll-driven refusal story, the interactive blueprint map with a 325-route gearbox explorer, the Science "proofs that run" trio (AGM convergence demo, pipeline flow, R² envelope chart), and the corpus made spatial (cover shelves, a knowledge-base radial map, an archive treemap).

Plan v2 (later the same day) re-centers the strategy on the Exhibition — the five-view research application promoted to "the Main Exhibition," a dedicated gallery-like route with a lobby, live-motion thumbnails, a guided tour, theme/language passthrough, deep links from every content page, and a mobile highlights reel. It states two hard constraints: the Program Coverage view "⛔ Excluded from the public build … so the gap data never enters the public bundle," verified "by grepping the emitted bundle for coverage strings before every deploy"; and a claim-discipline rule extended to visuals — every number in a graphic traceable, projected quantities never rendered solid, simulation outputs always labeled as simulation.

The goal, in short, is not "more images." It is a change in the *unit of argument* — from the paragraph to the instrument — enforced by a grammar, a pipeline, and guardrails. Divergence must therefore be assessed on three axes: what the pages argue with, whether the grammar and pipeline exist, and whether the guardrails bind.

## 3. The Architecture, As Found

The site is a Create React App single-page application (React 19, `react-scripts` 5, React Router 7, framer-motion 12) deployed on Vercel, fully bilingual (EN/FA with RTL), with one serverless function (`api/artifact-proxy.js`). All primary content is compiled into the application as JavaScript modules under `src/data/`: `copy.js` (165 KB), `libraryAssets.js` (70 KB), `knowledgeBase.js` (63 KB), `diagrams.js` (45 KB), `founder-bio.js` (35 KB), `multiAgentSystem.js` (30 KB), `artifacts.js` (21 KB), `facts.js` (6 KB) — roughly 430 KB of source text that ships, by construction, in the entry bundle, since `App.js` statically imports every page and every page statically imports its data. To the codebase's credit, the heavy libraries are dynamically imported (`mermaid` in `DiagramViewer.js`, `jspdf`/`jszip`/`file-saver` in `downloadService.js`), so library-level code splitting exists; route-level and data-level splitting do not.

Navigation exposes eighteen destinations in three groups, of which at least five are document-corpus surfaces (Knowledge Base, Artifact Gallery, Technical Library, Document Archive, plus the Methods audit page's document orientation). The marketing/research pages are assembled from a small kit — `Hero`, `SectionBlock`, `SectionBlockSticky`, `CTABand`, card grids — driven by `copy.js`. The Knowledge Base is an 8-part / 43-chapter / 158-section navigable tree whose section leaves render a placeholder sentence (`KnowledgeBaseReader.js:440`: "Content for this section is rendered from the source LaTeX/PDF document or injected via the content pipeline"). A document "cart" subsystem (context, widget, panel, client-side ZIP/PDF export) supports bundled downloads. Seven persistent chrome/overlay systems mount on every page: dual navigation bars, scroll-progress rail, back-to-top, cart widget, fact-engine panel, command palette, and cookie banner.

The visual layer as of the July 11 state comprises: thirteen static blueprint plates (`public/docs/svg/plates/P0–P14`, P7 and P10 absent from the sequence) placed as `<figure><img>` blocks on eleven pages with bilingual captions; three larger blueprint SVGs (`Master_Blueprint_Map`, `Epistemic_Gearbox_Stack`, `Metabolic_Memory_Reservoir`) also as static images; twenty-four Mermaid diagrams rendered client-side in a filterable gallery at the bottom of Architecture; twelve PDF cover thumbnails wired to eleven of the fifty curated library assets; four legacy `AbstractVisual` placeholder SVGs still in service on Science, Safety, and Technology; and the Exhibition — the Vite/D3/KaTeX sub-application living inside `src/signal-multiplexer-viz/`, built by `npm run build:exhibition` into `public/exhibition/` and embedded on `/{lang}/exhibition` through an iframe with `?view=` deep links.

This inventory is not nothing. The plates program alone gave every major page at least one honest, program-specific figure in a consistent captioned style, in both languages, within days. The exhibition embed correctly isolates D3 and KaTeX from the main bundle and passes view deep links from Home ("Enter the exhibition") and Safety ("Watch the chain refuse — live"). The Home stat tiles carry the first two standings chips ("measured," "proven") the site has ever rendered. These are real movements toward the goal, and the review's criticism should be read against that acknowledgment.

## 4. Divergence Analysis

### 4.1 The unit of argument is still the paragraph

On the plan's own definition — the page makes its argument visually first, prose demoted to captioning — no in-application page currently qualifies. Safety carries roughly 800 words of English body copy across six prose sections and two card grids, punctuated by four static plates; the scroll-driven refusal story, the G-ring, and the veto latency scale do not exist, and `SectionBlockSticky`, installed for exactly this purpose, is not used on the page. Science remains five prose sections with one manuscript plate and a decorative placeholder graphic; the AGM demo, pipeline animation, and envelope chart — the "proofs that run" that would distinguish the page from every competitor's — are absent, so the page *asserts* quadratic convergence in text where the plan intended the visitor to *watch* it. Perspective renders three essays, about 1,500 words, as undifferentiated paragraph streams beneath one plate; the editorial treatment (drop caps, pull quotes, spot illustrations) is absent. Methods is prose end-to-end after its pipeline plate; the audit verdict matrix — "the audit as a picture" — was never built. Architecture presents the blueprint map as an inert image: no pan/zoom, no hotspots, no side-panel register entries; the 325-route gearbox explorer, the plan's candidate for "the program's most original concept made playable," does not exist; the von Neumann crosswalk is a static comparison table rather than flip-cards; and the Mermaid gallery remains where the plan found it — at the bottom of one page, client-rendered.

The arithmetic of the divergence is stark. `copy.js` alone carries ≈4,400 words of English page copy (and its Persian mirror); the founder bio adds ≈2,700 more; the knowledge-base tree, library metadata, and diagram descriptions add thousands beyond that. Against this, the interactive instruments specified by the plans number ten; the number shipped is zero. Every visual that did ship is static, and every one of them was *added around* existing prose rather than substituted for it. The house pattern — visible identically on Safety, Science, Methods, Technology, Perspective, and Bio — is `<Hero>` + prose `SectionBlock`s + appended `<figure>`. The plan named this pattern as the anti-goal in its first paragraph.

### 4.2 The Exhibition: right centerpiece, wrong frame — and a breached guardrail

The v2 plan's strategic insight was sound and remains so: the five-view research application is the strongest public asset the program owns, and it shipped first, as recommended. But the Exhibition Hall as implemented is an ordinary content page — breadcrumb, text hero, prose placard, text room cards recycled from the Safety layer-card styles — wrapping an 82vh iframe. The lobby's live-motion thumbnails, the guided tour overlay, the theme and language bridge (the iframe receives only `?view=`, so a dark-mode Persian visitor gets the sub-app's own defaults), and the mobile highlights reel (the plan was explicit that dense instrument panels must not be responsive-squeezed) are all absent. Deep links shipped from Home and Safety but not from Science, Methods, or the Multi-Agent page, which embeds the older laboratory HTML instead of the Event Fabric room. The gallery, in other words, was delivered as an annex: the site points at the exhibition rather than being recomposed around it.

The graver matter is the guardrail. The evidence chain, each link verified directly in the working tree and the emitted artifact, reads as follows. Plan v2 §2.1 marks the Program Coverage view "⛔ Excluded from the public build," and §2.3/§5 mandate a build-time strip plus a pre-deploy grep of the emitted bundle. The mechanism was in fact implemented — `src/signal-multiplexer-viz/vite.config.js` aliases `ProgramCoverageMap` to a stub and `App.jsx` gates the view and its tab behind `VITE_EXHIBITION === '1'`. But the root `package.json` script that produces the deployed artifact reads `"build:exhibition": "cd src/signal-multiplexer-viz && npm ci && npx vite build --base=/exhibition/ && …"` — the flag is never set, so the curated-build branch never executes. Consequently the deployed bundle `public/exhibition/assets/index-xipKf2En.js` contains the "Program Coverage Map" view-switcher label, eleven `coverage:"GAP"` records, the full domain-by-domain subcategory table with chapter mappings and analyst notes, and internal references such as `main(8).tex`. The sub-app's own README states the coverage files are "physically absent from this copy — any build from this directory is coverage-free by construction"; the directory contains `ProgramCoverageMap.jsx`, `GapClosurePlan.jsx`, `ValidationFrontier.jsx`, and `data/programCoverage.js` (28.7 KB), all timestamped in the same July 11 session that produced the bundle. Above the iframe, the site itself completes the exposure: `Exhibition.js` lists `'coverage'` among `VALID_VIEWS`, and `copy.js` advertises the room in English and Persian — "11 explicit gaps with a prioritized closure plan" — under a section titled "The Four Rooms" that renders five cards. No CI or script performs the mandated bundle assertion; `vercel.json` additionally serves the bundle with a one-year immutable cache header, which means the artifact persists at its content-hashed URL regardless of subsequent fixes.

Two interpretations exist, and the repository cannot adjudicate between them — which is itself the finding. Either the coverage view was deliberately published (a defensible posture: update plan 1 §4.2.3, dated the *same day* as v2, praises the coverage map as "the single most persuasive honest-status artifact the program has produced" and directs it into the Knowledge Base), in which case plan v2, the README, the stub machinery, and the "Four Rooms" copy are all false statements now shipping alongside it; or the exposure is inadvertent, in which case sensitive competitive information — a prioritized inventory of exactly where the program lacks source material — is live. The architecture holds both postures simultaneously because no single authority binds sensitivity decisions to deployment. The original website-creation prompt contained a full public/gated/internal triage matrix; that governance culture never became a mechanism.

### 4.3 The grammar and the guardrails do not exist as systems

The standings legend — the plan's first-listed, cheapest, most differentiating item ("it costs a CSS file") — was never built as a component. Standings appear exactly twice as UI (two chips on the Home tiles) and elsewhere only as prose disclaimers. The blueprint token system (grid textures, registration marks, monospace figure captions, cyanotype dark mode) likewise does not exist; figures are styled by repeated inline-style blocks hardcoding `#fcfcfb` white grounds — which in dark mode produces glowing light rectangles, the opposite of the cyanotype direction, and reproduces the exact class of hardcoded-color defect the February contrast report catalogued. Motion, the plan's "narrowing" identity, is currently a 300 ms page-fade in `App.js` and nothing else.

The claim-discipline guardrails, extended to visuals by both plans, are breached in the visual layer itself. The Technology page's `StatsBand` hardcodes "100× More Efficient than GPU," "10× Lower Power Consumption," "1000+ Physics Calculations/sec," and "99.99% Reliability" — unlabeled, untraceable, and rendered solid — on the same site whose Home page states that the corpus's only measured number is the ~32 ns veto latency, and in the same July 11 session that polished the claim-disciplined exhibition placard. This is not a stale corner; it is a live self-contradiction between two surfaces of the current build, of exactly the kind the June audit ("the unlabeled performance claims we just removed") was supposed to have retired. Related hygiene drift compounds it: the exhibition placard's "runtime-verified (Playwright, zero console errors)" claim ships in `copy.js` while the repository carries no Playwright configuration or test files that reproduce the verification (the dependency exists in the sub-app's devDependencies; the harness does not travel with the claim); and asset counts disagree across surfaces (Home: "109 documented assets"; `libraryAssets.js`: 50 slugs; the public manifest: 65 file entries; the nav chip: "1,751 archived documents" against the hierarchy JSON's 1,775).

### 4.5 Why the divergence persists: five structural causes

The pattern above has causes in the architecture, and they will outlast any single sprint unless addressed as such.

**The content model privileges prose.** All argumentation lives as string literals in statically imported JavaScript modules. Adding a paragraph is a one-file edit with instant bilingual slots; adding a visual instrument requires a component, a stylesheet, token compliance, RTL and reduced-motion variants, an accessibility fallback, and a data source — none of which have shared infrastructure. An architecture is what it makes cheap; this one makes the anti-goal cheap.

**The toolchain has no build stage for visuals.** Create React App (a deprecated toolchain, here driving React 19) offers no static-generation or asset-pipeline hook, so every build-time item in the plans — pre-rendered Mermaid, cover generation, SVG hotspot injection, the bundle assertion itself — has nowhere natural to live, and the two that exist (`organizeLibrary.js`, `build:exhibition`) are manual scripts run ad hoc. The performance budget (LCP ≤ 2.5 s mid-tier mobile, CLS 0) is neither enforced nor measurable in this setup, and the entry bundle necessarily carries the entire textual corpus of every page before the first paint of any page.

**The information architecture is corpus-first.** Eighteen navigation destinations, of which five are document repositories and one — the flagship Knowledge Base, "8 parts · 43 chapters" — is a deep navigable tree whose leaves are placeholders. A visitor's most probable journey terminates in a list of documents or a stub, not an instrument. The exhibition, nominally the center of gravity, is one entry among eighteen; Home foregrounds it, the IA does not.

**Accretion without deletion.** The tree carries ~170 KB of dead legacy modules at `src/` root (`Knowledgebase.js`, `Knowledgebasereader.js`, `Knowledgebase-addendum.js`, `FactEngine.js`, `Jsonld.js` — an exact byte-duplicate of `utils/jsonld.js` — and `Knowledgebase.css`), an `_old` hero variant, two 25–40 KB unimported JSON schemas, a complete nested Vite application with its own lockfile inside `src/` (with `npm ci` executing inside the CRA source tree on every exhibition build), committed build artifacts in `public/exhibition/`, and two parallel styling systems (the bespoke token sheets and a configured-but-marginal Tailwind). Seven chrome overlays and a retail-style cart wrap every page of what the goal says should feel like a gallery. Each of these is a previous strategy still resident in the architecture; the plans' "one flagship room and four supporting galleries" presupposes subtraction that the process has never once performed.

**Process controls were removed rather than repaired.** `vercel.json` permanently disables ESLint at build — the residue of the February incident in which production silently pinned to a stale commit for weeks (three synchronized git branches, settings drift, failed builds). The forensics report that diagnosed it recommended standardization; the standardization chosen was to turn the gate off. There is no CI, no automated deploy verification, and no test coverage beyond the CRA default stub — which is how a mandated one-line grep assertion failed to exist at the exact moment it mattered.

## 5. Findings Ranked, With Remedies

**P0 — Resolve the coverage exposure, in whichever direction is actually intended.** If the view is sensitive: set `VITE_EXHIBITION=1` inside the `build:exhibition` script itself (not the shell), rebuild, remove the coverage room from `copy.js` (EN and FA) and `'coverage'` from `VALID_VIEWS`, add the grep assertion as a script that fails the build, and treat the already-published bundle as disclosed — it has been served under a one-year immutable cache at a stable hashed URL. If the view is now deliberately public: say so — update plan v2's ⛔, correct the sub-app README's false "physically absent" claim, reconcile "The Four Rooms" copy, and record the decision. Both branches cost hours; the untenable state is the current one, in which the deployment, the mechanism, the README, and two same-day strategy documents assert four different things.

**P0 — Remove or re-encode the Technology `StatsBand`.** Four unlabeled solid-rendered performance claims on a current page contradict the program's central brand claim and its own visual guardrails. Either delete the band or drive it from the standings register with honest values (the Home tiles show the pattern).

**P1 — Make standings and sensitivity a data structure, not a memory.** One machine-readable register (the `facts.bundle.json` pattern already points the way) in which every public figure, stat, and dataset carries a standing (measured / proven / projected / proposed) and a visibility class (public / gated / internal), consumed by components at render time and by the build at assert time. This single artifact operationalizes both the visual grammar and the guardrails, and it is the precondition for every "true spectacle" the plans describe.

**P1 — Build the legend and the tokens before any further set-pieces.** The standings-legend component plus the blueprint token sheet is the highest-leverage remaining item: it retrofits meaning onto the thirteen plates and twelve covers already shipped, gives dark mode its cyanotype identity, and replaces the inline-style figure blocks that currently violate the site's own token system.

**P1 — Reinstate process gates.** A minimal CI: build on push with lint re-enabled (fixing violations rather than disabling the linter), the bundle-sensitivity grep, a link/route check across both languages, and count-consistency assertions for the nav chips. The February forensics episode and the July guardrail failure are the same pathology — no automated relationship between what the documents mandate and what deploys.

**P2 — Ship one signature interactive as proof of pattern.** Not five; one. The gearbox route explorer (self-contained combinatorics, no simulation dependency) or the Safety scroll story (the component already exists) would establish the component/data/RTL/reduced-motion conventions every subsequent instrument reuses — converting the plan's thesis from a document into a precedent in the codebase.

**P2 — Give the asset pipeline a home by migrating off CRA.** A Vite or Next static-export migration is bounded (pages are thin `SectionBlock` compositions; the data layer ports unchanged; the sub-app is already Vite) and purchases route-level code splitting, build-time Mermaid pre-rendering and thumbnail generation, prerendered HTML for a corpus site whose SEO currently depends on client-side rendering behind an SPA rewrite, and a place for the assertions in P1 to run. Hoist `signal-multiplexer-viz` out of `src/` in the same motion.

**P2 — Reconcile the Knowledge Base with the honesty brand.** A 158-section navigable tree over placeholder leaves inverts the program's epistemic posture: it *renders* comprehensiveness that does not exist on the site. Either connect the content pipeline (the v3.0 corpus exists) or collapse the tree to published depth and let the plates-and-covers layer carry the map.

**P3 — Subtract.** Delete the dead root-level modules, the duplicate `jsonld`, the `_old` components, and the unimported schema JSONs; parameterize the ~44 duplicated routes to `/:lang/*`; remove the hardcoded deployment hostname from `App.js`; consolidate on one styling system; add the exhibition's theme/language bridge and a mobile fallback; extend covers to the remaining assets; fix the "Four Rooms" count wherever the coverage decision lands.

## 6. Concluding Assessment

The program's thesis is that engineering honesty is the product, and its visual strategy is unusually well conceived precisely because it is an *epistemic* strategy — standings as a look, demonstrations instead of metaphors, non-claims drawn on the chart. The website's divergence from the 100-percent-visual goal is therefore best understood not as missing decoration but as an unexecuted change in the architecture's unit of argument. Today the unit remains the paragraph: the pages narrate, the plates illustrate the narration, the corpus surfaces dominate the information architecture, and the one true instrument — the exhibition — is embedded as a foreign annex whose most sensitive room shipped to the public against the plan's explicit prohibition, under a README that says it cannot happen.

That last sentence is the review in miniature. The gap between this site and its goal is not a shortage of visual assets, talent, or even effort — July 11 alone produced the exhibition integration, thirteen wired plates, and a cover pipeline. The gap is that nothing in the architecture *binds* intention to artifact: not the content model (text is frictionless, instruments are bespoke), not the build (no stage where visuals are produced or verified), not the process (gates removed, assertions unwritten, plans mutually contradictory on the same day). Until some mechanism — the register, the CI assertions, the one proven interactive pattern — closes that loop, each future visual initiative will land the way the last one did: as figures appended to a text machine, with the guardrails living in documents the deploy never reads.
